# FinWise — Alcance y evolución

## 1. Por qué se separan dos alcances

FinWise tiene una visión amplia, pero la primera entrega académica necesita ser pequeña y comprobable. Por eso se distinguen:

- **MVP académico:** primera demo funcional con tres capacidades esenciales.
- **Proyecto ampliado:** evolución posterior con módulos adicionales.

Esta separación evita presentar como “mínimo” una aplicación demasiado grande para validar en poco tiempo.

## 2. Primera demo — MVP académico

La primera demo se concentra en un flujo de extremo a extremo:

1. registrar ingresos y gastos;
2. obtener el saldo líquido;
3. configurar obligaciones y una reserva de seguridad;
4. calcular el dinero disponible;
5. mostrar un resumen financiero sencillo.

El usuario debe poder comprender la diferencia entre lo que tiene en sus cuentas y lo que realmente puede gastar.

## 3. Siguiente etapa — núcleo financiero

Después de validar la primera demo se pueden incorporar:

- autenticación y perfil;
- múltiples cuentas financieras;
- categorías;
- edición y eliminación de transacciones;
- dashboard completo;
- presupuestos;
- metas de ahorro;
- alertas;
- proyección de fin de mes.

## 4. Segunda versión

Funciones que pueden ampliar el análisis financiero:

- suscripciones;
- administración avanzada de deudas;
- estrategias de pago;
- importación y exportación de datos;
- comparación entre meses;
- reportes;
- Financial Score;
- simulador financiero.

## 5. Funciones avanzadas

Posibles extensiones futuras:

- categorización inteligente;
- recomendaciones personalizadas;
- detección avanzada de patrones;
- asistente financiero conversacional;
- integración bancaria;
- finanzas compartidas;
- notificaciones push;
- aplicación móvil.

## 6. Principio de priorización

Toda función nueva debería aportar al menos a uno de estos objetivos:

> **Registrar — Analizar — Predecir — Recomendar**

Si una característica no ayuda a ninguno de ellos o no mejora la propuesta de valor principal, puede dejarse para una versión posterior.
